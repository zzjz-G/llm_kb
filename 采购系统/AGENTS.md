# 课题组耗材采购与库存管理系统

## 产品概述
高校课题组耗材采购申请与库存进销存管理系统，B/S架构，电脑浏览器访问。两级权限：学生账号（学号登录）、管理员（老师）账号。轻量化、简洁科研风格。

## 技术架构

### 账号体系
- 自建账号体系：学号 + 密码登录（JWT token）
- 两级角色：admin（管理员/老师）、student（学生）
- 管理员创建/禁用/重置学生账号
- 学生完善收货信息（姓名、手机号、收件地址）

### 数据模型
| 表 | 说明 |
|---|---|
| lab_users | 用户表（学生+管理员，学号作为登录名） |
| purchase_orders | 采购订单主表 |
| purchase_items | 采购订单明细表（一单多品） |
| inventory | 库存台账 |
| operation_logs | 操作日志 |

### 核心流程
1. 学生提交采购申请（一单多品，提交时自动检索库存预警）
2. 管理员审核（通过/驳回）
3. 管理员登记入库 → 订单状态：已入库
4. 学生补填存放位置 + 剩余数量 → 订单状态：已完成
5. 管理员维护库存台账（手动建库、领用消耗、修改）
6. 拦截规则：学生名下有"已入库"但未补填的单据，不能提交新申请

## 设计规范

### 场景约束
- 产品定位：课题组师生用它管理耗材采购与库存，用起来像实验室台账记录本，而不是又一个笨重的ERP系统
- 应用类型：业务工具；判定理由：数据长期累积、多人协作、批量处理台账与单据
- 使用者与场合：高校课题组老师（管理员）和学生，长时间在工位电脑上操作
- 视觉主角：库存台账表格与采购单据表格
- 信息密度：高，一屏多看数据，密而有序
- 页面结构：全局侧栏（学生端/管理端不同导航），登录后展示左侧导航 + 右侧内容区；选择理由：多个并列业务模块（采购申请、我的订单、库存台账、账号管理等）需要频繁切换
- 工作面板：无
- 用户风格原话：极简科研风格，页面干净整洁，表格规整；表单优先下拉选择，减少文字输入；适配电脑浏览器，适合高校课题组长期使用
- 应用身份：展示品牌区（侧栏顶部应用名）；理由：多模块持续导航需要识别当前应用

## 后端架构

### 模块划分
- auth 模块：登录、登出、获取当前用户信息
- users 模块：学生账号管理（管理员）、个人信息修改（学生）
- purchase 模块：采购订单CRUD、审核、入库、补填、库存预警检索
- inventory 模块：库存台账CRUD、领用消耗、关键词检索
- logs 模块：操作日志查询
- export 模块：Excel导出（供货商订货单、库存台账）

### 认证方式
- JWT token（HS256），存在 localStorage
- 请求头 Authorization: Bearer <token>
- Guard 中间件校验 token，解析用户信息挂载到 req.user

### 权限规则
- 学生：只能看自己的订单，库存台账隐藏价格字段
- 管理员：全部数据可见，所有操作权限
- 使用自定义装饰器 @Roles(['admin', 'student']) + RoleGuard
