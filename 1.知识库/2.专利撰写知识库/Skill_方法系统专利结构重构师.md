# Skill：方法+系统类发明专利「独权减负、详情下沉、全文对齐」修改规范

> **样本来源**：只有一对样本，即《基于数字孪生的多机器人协同焊接智能规划控制方法及系统》的初稿（v9）和定稿（改稿1120）。
> **可信度**：单样本归纳。可以作为起草或修改时的参考框架，不能当作通用标准。使用前请先读第5节「适用边界与局限性」。

---

## 1. Skill 名称与定位

**名称**：方法系统专利结构重构师（Claim-Restructure-CN）

**主要适用对象**
- **专利类型**：中国发明专利，主题为「方法 + 系统」，属于计算机、控制或智能制造领域（如工业机器人、数字孪生、算法驱动的工艺控制）。
- **技术方案形态**：方法分成多个阶段（S1…Sn 流程式），系统由多个模块组成，并且包含大量算法细节和数值参数。

**主要适用场景**
1. 初稿把所有技术细节（算法、数值、公式）都写进独立权利要求1，导致保护范围过窄。
2. 权利要求书和说明书「发明内容」不对应，术语前后不一致。
3. 权利要求里出现的要素（如某个子模型），说明书里没有单独展开。
4. 想把细节「下沉」到说明书，作为后续答复审查意见时的修改储备。

**使用方式**：输入初稿全文后，依次执行：第2节逐条核查 → 第3节排查错误 → 第4节套用策略 → 第6节自检。输出修改后的文本和修改说明。

## 2. 核心撰写规则（Do's）

### 2.1 权利要求书

**R1. 独立方法权利要求只保留「步骤骨架 + 步骤间的输入输出链」**
- 每个步骤写成「步骤Sx、动作名称，（获取/以获取）中间产物」。
- 步骤之间用定义好的中间产物衔接，形成一条清楚的逻辑链。
  - 定稿示例：「S1……获取**工作站状态**」→「S2、基于**工作站状态**……获取**任务分配结果**」→「S3、基于**任务分配结果**……获取**协同运动路径和时间调度表**」→「S4、将……**协同运动路径、时间调度表**……发送至机器人控制器」。
- 算法名称、数值范围、公式、阈值都不写进独立权利要求。

**R2. 从属权利要求按「一步一项」展开，子步骤加字母编号**
- 采用「根据权利要求1所述的……方法，其特征在于，步骤S2具体包括：步骤S2A、……；步骤S2B、……」的格式。
- 每项从属权利要求只限定一个步骤，层次清楚，便于以后逐项合并。
- 最核心的区别特征放在第一层从属权利要求里。定稿就把「NSGA-II + 两段式编码」放在了权3。

**R3. 独立系统权利要求只写「模块组成 + 模块间数据流向」**
- 依次写出：模块清单（附图标记加括号，如「数字孪生建模模块（1）」）→ 谁向谁提供什么数据 → 谁把什么结果回传给谁。
- 模块内部的算法、周期参数、子模块细节不写进系统独立权利要求。

**R4. 权利要求主题名称与发明名称保持一致**
- 定稿把「……协同焊接规划控制方法」统一成「……协同焊接**智能**规划控制方法」，与发明名称一致。

**R5. 以「或」表达并列择一**
- 定稿把「调整焊接电流、焊接电压，**和/或**在保证……」改成了「……，**或**在保证……」。这是撰写偏好，并非法定要求，见第5节。

### 2.2 说明书 · 发明内容

**R6. 发明内容先给出一段与权利要求逐步对应的「完整技术方案」**
- 格式：「一种……方法，包括：步骤S1、……步骤S1A、……」，步骤编号与权利要求完全一致。
- 每个步骤下保留初稿独立权利要求中的全部细节，相当于把初稿权1的内容「平移」到这里。

**R7. 原从属权利要求的细节逐条改写为「优选地，……」段落**
- 初稿中关于时钟同步、碰撞检测阈值、同步误差公式、降阶模型、DDPG、多模态网络的各项从属权利要求，在定稿中都变成了「优选地」段落。
- 每段开头写明它对应哪一步，如「优选地，步骤S3B中的……」，方便以后答复审查意见时引入权利要求。

**R8. 用「综上」段落收束核心发明构思**
- 定稿把初稿中作为独立权利要求的「同一孪生模型同时驱动各环节、闭环回写」改写成说明书里的「综上」段，作为发明构思的总结。

**R9. 权利要求里列出的每个要素，说明书里都要有专门的展开段**
- 初稿权1列出5个子模型，说明书却只展开了3个。定稿补写了「工件热变形模型」（有限元热-力耦合 + POD/RBF降阶）和「环境模型」（静态/动态要素、深度数据更新）两段。
- 检查方法：对权利要求中的每个名词性要素，在说明书里检索是否有「输入—处理—输出—校准方式」四项描述。

**R10. 为新引入的上位概念给出定义句**
- 定义句的格式是「所述X包括A、B和C」或「……中的机器人记作'X'」。
- 定稿示例：
  - 「工作站状态包括：机器人的位姿、工件状态……」
  - 「协同组中的机器人记作'协同机器人'」
  - 「协同运动路径包括运动轨迹、速度曲线」，并与「时间调度表」并列，不再相互包含。

### 2.3 说明书 · 其他部分

**R11. 技术领域用「本发明属于……技术领域，具体涉及……」**

**R12. 发明目的直接陈述目标**
- 写「本发明的目的在于提供……，实现……」，不写「克服现有技术的不足」这类空泛开头。

**R13. 效果段标题用「与现有技术相比，本发明的优点为：」，并按（1）（2）…与各环节逐条对应**

**R14. 具体实施方式开头加标准声明，结尾加保护范围声明**
- 开头：「下面将结合示意图对本发明的……进行更详细的描述，其中表示了本发明的优选实施例……」。
- 结尾：「上述仅为本发明的优选实施例而已，并不对本发明起到任何限制作用……仍属于本发明的保护范围之内。」

**R15. 实施例标题只写「实施例1/2/3」，不加小标题；实施例主题要与内容一致**
- 实施例2只讲方法，定稿就把「方法及系统」改成了「方法」。

**R16. 首次出现时用括注把权利要求用语和实施例用语对齐**
- 示例：「物理工作站（多机器人焊接工作站）」「焊接参数（工艺参数）」「焊接位置（焊缝空间坐标，即焊缝的三维坐标）」。

**R17. 说明书里的具体实施步骤要补上权利要求中出现的输入项**
- 初稿权利要求写了「根据……和数字孪生模型输出的工作站状态」，但实施例的任务分解没有这项输入。定稿在实施例S2中补上了。

### 2.4 摘要

**R18. 摘要以「本发明提出了一种……」开头，按步骤顺序概述方案，以一句效果收尾，控制在300字以内**

### 2.5 术语与格式

**R19. 同一概念全文只用一个词**
- 定稿的统一方向：「工件变形模型」→「工件热变形模型」；「焊接过程监测数据」→「焊接过程感知数据」；「预测状态」→「工作站状态 / 工作站预测状态」。

**R20. 长段落按「一句一事」拆成短段**
- 每个参数组、每条策略、每个公式定义各占一段。

**R21. 公式和变量统一用 Word 公式对象**
- 正文里不夹杂 `e_s=|s_i−s_j|` 这类纯文本写法。

## 3. 避坑指南（Don'ts）

| # | 不要这样做 | 初稿中的表现 | 定稿中的处理 |
|---|---|---|---|
| D1 | **把实施细节堆进独立权利要求** | 权1是一个数百字的长段，含传感器清单、四个优化目标、包络构成、调速限制等 | 权1只保留6个步骤骨架 |
| D2 | **用纯功能或结果性的描述单独撰写一项独立权利要求** | 权2「由同一实时更新的数字孪生模型同时驱动……」，没有具体手段 | 删除，降为说明书中的「优选地」和「综上」段 |
| D3 | **系统权利要求塞入算法细节，并引用全部方法权利要求** | 权10写入双椭球热源、100–500ms周期，并以「实现权利要求1至9中任一项所述方法」收尾 | 只保留模块和数据流 |
| D4 | **权利要求里列了要素，说明书却没有展开** | 工件变形模型、环境模型只出现名称 | 补写专门段落 |
| D5 | **相近概念混用** | 「工件变形模型 / 热变形模型」「监测数据 / 感知数据」并存；「协同运动路径」有时包含时间调度表，有时不包含 | 统一术语，并给出定义句 |
| D6 | **用空泛套话开篇** | 「克服现有技术的不足」 | 删除 |
| D7 | **在摘要中加「摘要附图：图1」这类说明文字** | 有 | 删除；摘要附图在请求书里另行指定 |
| D8 | **实施例标题带小标题，或主题与内容不符** | 「实施例2：方法流程」，正文写「方法及系统」 | 改为「实施例2」，主题改为「方法」 |
| D9 | **具体实施方式没有首尾的标准声明** | 无 | 补齐 |

## 4. 修改策略库

### 策略A：「金字塔下沉」，独权扩范围、细节作储备
- **要解决的问题**：独立权利要求过窄，竞争对手只要改动任意一个参数就能绕开。
- **操作步骤**：
  1. 从初稿独权里提取「步骤名称 + 中间产物」，作为新的独权。
  2. 把每个步骤的核心手段写成一层从属权利要求。
  3. 把数值、公式、可替换算法全部写成说明书里的「优选地」段落。
- **原理**：答复审查意见时，只要修改不超出原说明书和权利要求书记载的范围（专利法第33条），就可以把说明书里的「优选地」内容并入权利要求，缩小保护范围以克服缺陷。
- **代价**：独权很可能在首次审查意见中因新颖性或创造性被驳回，需要预留答复轮次。

### 策略B：「中间产物锚定」，解决步骤之间缺少引用基础
- **要解决的问题**：步骤上位化以后，后一步缺少引用基础。
- **操作**：给每一步定义一个输出名词（如工作站状态、任务分配结果、协同运动路径），后一步以「基于所述X」开头。在说明书里给每个名词写定义句。

### 策略C：「要素—段落一一对应」，补强说明书支持
- **要解决的问题**：权利要求得不到说明书支持（专利法第26条第4款），或公开不充分（第26条第3款）。
- **操作**：在权利要求中，「包括A、B、C……」列出的每一项都要在说明书里有独立段落，写明它的输入、方法、输出和校准方式。

### 策略D：「发明内容镜像」，保证技术方案的一致性
- **操作**：发明内容的第一部分逐字对应权利要求（步骤编号相同），第二部分写「优选地」，第三部分写「综上」总结构思，最后保留原有的环节概述和效果。

### 策略E：「独权降级」，处理纯构思类权利要求
- **要解决的问题**：某项权利要求只有构思（如「同一模型驱动全部环节」），没有具体手段，容易被认定为不清楚或缺少必要技术特征。
- **操作**：把它从权利要求中移出，作为说明书「综上」段，或作为某一从属权利要求的附加特征。

### 策略F：「术语收敛」
- **操作**：全文检索同义或近义词，定下一个主术语。首次出现时用括注关联其他写法，此后全文只用主术语。

## 5. 适用边界与局限性声明（重要）

### 5.1 样本局限
- 结论只来自**一对样本、一个技术领域（多机器人焊接 / 数字孪生）、一位代理人的修改风格**，无法区分哪些是规范要求，哪些只是个人偏好。
- 两份文件之间可能还有多轮中间稿，审查意见、客户意见等修改动因不可见。
- 本 Skill 只能归纳出「改了什么」，**无法确认「为什么这样改」**。

### 5.2 定稿本身仍有瑕疵，以下做法不应照搬
1. **独立权利要求1可能过于上位**
   - S5「多机器人焊接质量协同保障」、S6「数字孪生模型在线更新」只有名称，没有手段。
   - 这有被认定为不清楚，或缺少解决技术问题所必需的技术特征的风险；新颖性和创造性方面也比较脆弱。
   - 处理建议：每个步骤至少保留一个区别性的技术手段，并做现有技术检索后再确定上位化程度，不要机械地只写步骤名称。
2. **从属权利要求的层次偏薄**
   - 定稿共7项权利要求，S6没有对应的从属权利要求；数值、算法类的防御层全部移到了说明书。
   - 处理建议：在10项免费额度内，把核心区别特征（如全机几何包络碰撞检测、交叉耦合同步误差定义、子任务级模型回写）各写成一项从属权利要求，预先搭好防御阵地。
3. **存在引用基础缺失**
   - 权5中的「协同机器人」「工艺窗口」在权1里没有出现，缺少引用基础。
4. **说明书里引用了权利要求**
   - 定稿说明书写了「实现权利要求所述方法的步骤和功能」。按审查指南，说明书不宜引用权利要求，应改为「实现上述方法的步骤」。
5. **术语没有完全统一**
   - 「热变形模型」和「工件热变形模型」仍然并存；「工作站状态」和「工作站预测状态」在权5与说明书中的对应关系也不够清晰。
6. **格式和文字错误**
   - 权利要求中有断行（「以获取\n各机器人」「任务分配结果\n；其中」「步骤\nS4」），权7有病句（「生成包含协同运动路径和时间调度表」）。
   - 声明句中「对于本领域技术人员的广泛知道」不通顺，应改为「广泛教导」一类表述。
7. **摘要信息可能不完整**
   - 定稿删掉了「属于……技术领域，用于解决……问题」。摘要按规定应写明所属技术领域、要解决的技术问题和主要技术方案，这一改法**不建议推广**。

### 5.3 以下场景必须由人工判断
- **授权前景与权利要求范围**：需要结合现有技术检索结果，确定独权的上位化程度。本 Skill 不做检索，也不判断新颖性和创造性。
- **非方法 / 系统类专利**：产品结构、化学医药、生物、材料组合物等领域的撰写逻辑完全不同（如马库什权利要求、实验数据支撑），不适用本 Skill。
- **实用新型、外观设计、PCT / 海外申请**：美国、欧洲等地区对功能性限定、手段加功能（means-plus-function）的处理不同，计算机实施发明的可专利性标准也不同，「下沉细节」的策略需要重新评估。
- **答复审查意见阶段**：修改受专利法第33条约束，答复后的修改还要针对通知书指出的缺陷。本 Skill 的「扩范围」策略**只适用于申请前撰写阶段**。
- **涉及算法、商业方法或智力活动规则的方案**：需要另外按审查指南中关于包含算法特征的发明的规定，论证方案的技术性（技术手段、技术问题、技术效果）。
- **客户有明确商业目标**：例如需要尽快授权，或需要保护某个具体参数。这时范围取舍要以客户意见为准。
- **初稿已有官方审查意见**：要以审查意见指出的缺陷为主线修改，不能套用本 Skill 的通用流程。

## 6. 修改完成后的自检清单

- [ ] 独权每个步骤都有「动作 + 产出」，后一步都以前一步的产出为输入。
- [ ] 每个步骤至少保留一个区别性技术手段（防止 5.2-1 中的风险）。
- [ ] 每项从属权利要求只限定一个步骤或一个要素，并且有引用基础。
- [ ] 权利要求中的每个要素和术语，在说明书里都有定义或展开段落。
- [ ] 发明内容中的技术方案与权利要求的步骤编号、用词一一对应。
- [ ] 每项原从属权利要求的细节都在说明书中以「优选地」形式保留。
- [ ] 全文同一概念只有一个主术语。
- [ ] 说明书中没有出现「如权利要求X所述」这类引用。
- [ ] 摘要写明了技术领域、技术问题、方案要点和效果，不超过300字。
- [ ] 没有断行、病句，公式统一用公式对象。
- [ ] 具体实施方式首尾都有标准声明，实施例标题和主题一致。
